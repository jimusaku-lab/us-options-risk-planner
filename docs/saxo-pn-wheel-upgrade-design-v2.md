## 1. 改訂の目的

これまでの手入力型パイロットは、JPYを主軸にした建玉管理として成立している。

ただし、サクソバンク証券で実際に運用する前提では、次の設計が不足していた。

- P口座とN口座の決済通貨差
- N口座を主戦場にしたUSDベースのホイール戦略
- P口座で取得した株式をN口座へ株式移管する流れ
- N口座内で、カバードコール、株式売却、プット売り、株式取得を循環させる管理
- ショートストラングル等で発生する、現物株を保有しないコール売りの上方向リスクと撤退ルール
- 最終出金時だけ円転するという為替設計

本設計書は、これらをアプリの正式なバックグラウンドロジックとして組み込み、以後の実装工程を明確にする。

## 2. 最終目標

最終目標は、サクソバンク証券のP/N口座構造に合わせて、米国株オプションの建玉、株式取得、株式移管、カバードコール、プット売り、税務区分、為替換算を一貫して管理できるアプリにすること。

特にホイール戦略は、原則として **N口座内でUSDベースで回す**。

```text
N口座でUSD保有
→ N口座でプット売り
→ 権利行使でN口座に株式取得
→ N口座でカバードコール
→ 権利行使で株式売却
→ N口座にUSDが残る
→ N口座で再購入または再度プット売り
```

P口座は、円資金から入口を作る補助ルートとして扱う。

```text
P口座でプット売り
→ 権利行使でP口座に株式取得
→ P口座からN口座へ株式移管
→ 以後はN口座ホイールへ合流
```

このアプリは、今後Saxo read-only連携を入れる場合でも、発注はしない。最終判断と発注はユーザーがSaxo画面で行う。

## 3. 重要な設計原則

### 3.0 DEMO口座は本番N口座相当として扱わない

SaxoTraderGOのDEMO口座は、米国株式・米国株式オプションの価格や建玉損益がUSDで表示される一方、画面下部の口座通貨、現金残高、買付可能額、評価額はJPYで表示される。

そのため、アプリ上では本番N口座相当として扱わず、次の3分類で扱う。

```ts
type AccountEnvironment =
  | "DEMO_JPY_BASE"
  | "PROD_P_JPY_SETTLEMENT"
  | "PROD_N_USD_SETTLEMENT";
```

- `DEMO_JPY_BASE`: デモ・テスト用。USD建て商品をJPY口座で管理している状態
- `PROD_P_JPY_SETTLEMENT`: 本番P口座。JPY決済
- `PROD_N_USD_SETTLEMENT`: 本番N口座。USD決済

DEMOワークスペースでは、口座全体カードにN口座欄を表示しない。

DEMO表示:

```text
DEMO / JPYベース
証拠金使用率
現金残高
必要証拠金など、Saxoデモ画面下部でJPY表示される項目
```

DEMOで非表示にするもの:

- N口座
- USD残高
- N口座証拠金使用率
- N口座ホイール用USD台帳

REALワークスペースの場合だけ、P口座とN口座を分けて表示する。

既存データの移行:

- 既存DEMOワークスペース: `DEMO_JPY_BASE`
- 既存REALワークスペースで口座種別がないもの: 原則 `PROD_P_JPY_SETTLEMENT`
- REAL側は必要に応じてユーザーがN口座へ変更できるようにする

注意:

- `DEMO_JPY_BASE` は本番P口座と完全に同じではない
- 画面上は「P口座」ではなく「DEMO / JPYベース」と表記する
- DEMO口座はP口座ロジックの初期テストには使える
- DEMO口座をN口座ロジック、USD残高管理、JPY→USD資金振替、USD取得レート管理の検証には使わない

### 3.1 P/N口座を合算しない

P口座とN口座は、同じサクソバンク証券内の外国株式等オプション口座であっても、アプリ上は別口座として扱う。

```ts
type SaxoAccountCode = "P" | "N";
type Currency = "JPY" | "USD";
```

- P口座: JPY決済
- N口座: USD決済
- 証拠金、現金残高、株式保有、オプション建玉は口座別に管理する
- P口座のJPY残高をN口座の余力として扱わない
- N口座のUSD残高をP口座の余力として扱わない

### 3.2 N口座の損益はUSDが主

N口座では、プレミアム、手数料、株式売買代金、実現損益、累積ホイール損益をUSDで管理する。

JPY表示は参考換算に限定する。

```text
N口座のJPY換算額は、表示用USD/JPYによる参考値です。
円転または税務上の確定損益とは異なる可能性があります。
```

### 3.3 為替は3種類に分ける

1. P口座の取引時適用為替
2. N口座の参考表示用USD/JPY
3. USDをJPYに戻す出金・円転時の為替

N口座内でホイールを回している間、USD建て損益は為替更新で変えない。

### 3.4 P口座の円転コストは二重計上しない

P口座でブローカー実明細のJPY決済額、JPY手数料、適用為替が分かる場合、それを優先する。

アプリ側で一律に0.25%を上乗せしない。

0.25%は、JPY⇔USDの資金振替イベントの推定時だけ既定値として使う。

### 3.5 税務区分は分ける

アプリ上は次を別区分として表示する。

- オプション損益: 先物取引に係る雑所得等
- 株式売却損益: 上場株式等の譲渡所得等
- 為替差損益: 今回は厳密計算の対象外。出金・円転イベントとして記録し、参考表示から始める

本アプリの税額は概算であり、申告用の確定値ではない。

## 4. 口座と台帳のデータ設計

### 4.1 口座マスタ

```ts
type BrokerAccount = {
  id: string;
  broker: "SAXO_BANK_JP";
  accountCode: "P" | "N";
  displayName: string;
  baseCurrency: "JPY" | "USD";
  settlementCurrency: "JPY" | "USD";
  productType: "FOREIGN_STOCK_INDEX_OPTIONS";
};
```

表示例:

- `P: 外国株式等オプション（円建て / JPY決済）`
- `N: 外国株式等オプション（ドル建て / USD決済）`

### 4.2 口座状態

現在の `AccountInputs` はJPY前提なので、P/N別に拡張する。

```ts
type AccountState = {
  accountCode: "P" | "N";
  currency: "JPY" | "USD";
  cashBalance: number;
  marginAvailable: number;
  buyingPower?: number;
  marginUsagePercent: number;
  accountValue?: number;
  updatedAt: string;
  cashAdjustments?: AccountCashAdjustment[];
};

type AccountCashAdjustment = {
  id: string;
  sourceType: "option_close_execution";
  sourceSimulationId: string;
  sourceExecutionId: string;
  accountCode: "P" | "N";
  currency: "JPY" | "USD";
  amount: number;
  label: string;
  appliedAt: string;
  memo?: string;
};
```

P口座:

- 現金残高 JPY
- 買付可能額 JPY
- 口座純資産 JPY
- 必要証拠金余力 JPY
- 証拠金使用率

N口座:

- USD現金残高
- USD買付可能額
- USD口座純資産
- 必要証拠金余力 USD
- 証拠金使用率
- 参考JPY換算

SaxoTraderGOの画面下部に表示される項目は `必要証拠金` ではなく `必要証拠金余力` である。アプリの口座全体カードでは、利用者がSaxo画面からそのまま転記できるよう、入力ラベルを `必要証拠金余力` に統一する。

設計上の意味:

```text
必要証拠金余力 = 追加で証拠金として使える余力
必要証拠金 = 既存建玉で拘束・要求されている証拠金
```

本アプリでは、Saxo画面下部に表示される `必要証拠金余力` を入力対象にする。`必要証拠金` そのものをユーザーに探させない。

計算上の扱い:

- `証拠金使用率` はSaxo表示値をそのまま入力し、警告判定に使う
- `必要証拠金余力` は、口座全体の余力確認と参考表示に使う
- P売り権利行使時の買受資金チェックは、原則として `現金残高` または `買付可能額` と比較する
- `必要証拠金余力` を、株の買受資金そのものとして扱わない
- 分母計算に使う個別建玉の証拠金は、従来どおり建玉入力側の `チケット表示証拠金` と `証拠金バッファ` から計算する

既存データ互換:

- 旧 `marginRequirement` は読み込み時に `marginAvailable` へ移行する
- 旧JSONの値を失わない
- UI上は `必要証拠金余力` と表示し、`必要証拠金` とは表示しない

## 5. 為替・資金振替・出金設計

### 5.1 FX_TRANSFER

JPY⇔USDの資金振替は、オプション取引とは別イベントとして扱う。

```ts
type FxTransferEvent = {
  id: string;
  direction: "JPY_TO_USD" | "USD_TO_JPY";
  fromAccountCode: "P" | "N" | "OTHER_JPY" | "OTHER_USD";
  toAccountCode: "P" | "N" | "OTHER_JPY" | "OTHER_USD";
  fromCurrency: "JPY" | "USD";
  toCurrency: "JPY" | "USD";
  fromAmount: number;
  toAmount: number;
  appliedFxRate: number;
  fxCostRate?: number;
  occurredAt: string;
  source: "manual" | "broker_statement" | "app_estimate";
};
```

推定時の既定値:

```ts
const DEFAULT_SAXO_TRANSFER_FX_COST_RATE = 0.0025;
```

ただし、実明細の `fromAmount`, `toAmount`, `appliedFxRate` がある場合はそれを優先する。

### 5.2 N口座からの最終出金

N口座ホイールで得たUSD利益は、N口座内ではUSD利益として管理する。

最終的に出金したい場合のみ、出金・円転イベントを記録する。

```text
N口座USD残高
→ USD_TO_JPY出金・円転
→ その時点の為替でJPY換算
```

このイベントは、N口座内ホイールの運用成績とは別に表示する。

## 6. 株式移管設計

### 6.1 P→N株式移管イベント

P口座でプット売りが権利行使され株式を取得した場合、その株式をN口座へ移管する運用を想定する。

```ts
type StockTransferEvent = {
  id: string;
  ticker: string;
  fromAccountCode: "P" | "N";
  toAccountCode: "P" | "N";
  shares: number;
  transferDate: string;
  costBasisUSD: number;
  sourceSimulationId?: string;
  destinationWheelCycleId?: string;
  memo?: string;
};
```

株式移管は売却ではないため、原則として以下の扱いにする。

- オプション損益に含めない
- 株式譲渡損益に含めない
- 為替差損益に含めない
- 株数と取得単価をN口座側へ引き継ぐ
- N口座ホイールの `stock_holding` フェーズへ合流させる

### 6.2 P口座で株式が残る場合の警告

P口座で株式取得済みだがN口座へ移管していない場合、次の注意を表示する。

```text
P口座で取得した株式が残っています。
N口座へ株式移管してカバードコール管理へ進めるか確認してください。
```

## 7. N口座ホイール戦略設計

### 7.1 ホイールの基本単位

ホイールは銘柄ごとに管理する。

```text
1銘柄 = 1ホイールサイクル
```

NVDA、AMZN、NFLXなど、銘柄ごとにカードを表示する。

### 7.2 ホイールフェーズ

```ts
type WheelPhase =
  | "n_cash"
  | "n_short_put"
  | "n_stock_holding"
  | "n_covered_call"
  | "n_called_away"
  | "p_short_put"
  | "p_assigned_stock"
  | "p_to_n_transfer_pending"
  | "cycle_closed";
```

標準ルート:

```text
N現金待機
→ Nプット売り中
→ N株式保有中
→ Nカバードコール中
→ N株式売却済み
→ N現金待機
```

P口座合流ルート:

```text
Pプット売り中
→ P株式取得済み
→ P→N株式移管待ち
→ N株式保有中
→ Nカバードコール中
```

P口座合流ルートは、N口座ホイール本体ではなく「N口座ホイールへ合流する前段階」として扱う。P口座でプット売りをしているだけの状態では、N口座の現金待機を「済」と表示しない。N口座にUSD現金がない、またはN口座で実際に建玉・株式保有がない場合は、N口座側のフェーズを進行済みに見せない。

表示上は次のように分ける。

```text
P口座準備ルート:
Pプット売り中
→ P株式取得済み
→ P→N移管待ち

N口座ホイール本体:
N現金待機
→ Nプット売り中
→ N株式保有中
→ Nカバードコール中
→ N株式売却済み
```

P口座準備ルートのカード名は `N口座ホイール` と断定せず、`ホイール準備中（P口座）` または `P口座からN口座への合流準備` とする。N口座へ移管済み、またはN口座で建玉を開始した段階で `N口座ホイール` と表示する。

### 7.3 ホイールサイクル

```ts
type WheelCycle = {
  id: string;
  ticker: string;
  primaryAccountCode: "N";
  currentPhase: WheelPhase;
  currentAccountCode: "P" | "N";
  currentShares: number;
  averageCostUSD: number;
  usdCashImpact: number;
  cumulativePremiumUSD: number;
  cumulativeStockRealizedPnlUSD: number;
  cumulativeFeesUSD: number;
  cumulativeTotalPnlUSD: number;
  referenceFxRateJPY?: number;
  eventIds: string[];
  linkedSimulationIds: string[];
  openedAt: string;
  closedAt?: string;
  memo?: string;
};
```

`primaryAccountCode: "N"` は「最終的にN口座でホイールを回す設計上の主口座」を表す。現在の実建玉口座ではない。画面上で `主口座 N / 現在 N` のように表示すると誤解しやすいため、次のように表示する。

- P口座準備中: `現在: P口座 / N口座合流前`
- P→N移管待ち: `現在: P口座 / N口座へ移管待ち`
- N口座で運用中: `現在: N口座ホイール`

`主口座 N` という内部概念は、利用者向けの常時表示から外すか、ヘルプ内だけで説明する。

### 7.4 ホイールイベント

```ts
type WheelEvent =
  | ShortPutOpenedEvent
  | ShortPutClosedEvent
  | PutAssignedEvent
  | StockTransferEvent
  | StockPurchaseEvent
  | CoveredCallOpenedEvent
  | CoveredCallClosedEvent
  | CallAssignedEvent
  | StockSoldEvent
  | FxTransferEvent
  | ManualAdjustmentEvent;
```

イベント履歴は時系列で表示する。

```text
日付 | イベント | 口座 | 内容 | USD損益 | 株数変化 | フェーズ
```

### 7.5 ホイール可視化

画面下部のホイール戦略は、表だけではなく、色付きステップで現在地を示す。

```text
N現金待機 ─ Nプット売り ─ N株式保有 ─ Nカバードコール ─ N株式売却
  済           済           済           現在             未
```

色:

- 灰色: 未到達または該当なし
- 緑: 通過済み
- 青: 現在
- 黄: 注意
- 赤: 対応が必要

ステップの「済」は、その口座で実際に通過した状態だけに使う。P口座でプット売り中の場合、N口座現金待機を通過済みとして緑表示しない。N口座の現金が0 USDで、N口座側の建玉・株式保有もない場合は、N口座ステップは未到達として表示する。

P口座準備中の例:

```text
NVDA  ホイール準備中（P口座）
現在: P口座でプット売り中 / N口座合流前

Pプット売り ─ P株式取得 ─ P→N移管待ち ─ N株式保有 ─ Nカバードコール
  現在           未             未             未             未
```

この状態では、N口座の累積プレミアム、N口座現金、N口座ホイール損益を0のまま「済」扱いにしない。

カード例:

```text
NVDA  N口座ホイール
現在: Nカバードコール中
累積プレミアム +$428
累積損益 +$612
保有株数 100株 / 平均取得 $200.00

N現金待機 ─ Nプット売り ─ N株式保有 ─ Nカバードコール ─ N株式売却
  済           済           済           現在             未

次の候補: Cを満期まで保有するか、買戻しで閉じるかを確認
```

### 7.6 建玉管理との役割分担

建玉ダッシュボード:

- いま存在する1件ごとの建玉
- 注文前、建玉中、決済済み、権利行使済み、満期終了

ホイール戦略:

- 同じ銘柄の一連の履歴
- 累積プレミアム
- 累積株式売買損益
- 現在フェーズ
- 次に取る候補アクション

### 8.1.1 公開版の外部株価・為替取得モード

一般公開用バージョンでは、初期状態では外部株価・為替取得をOFFにする。ただし、利用者が明示的に同意した場合だけ、外部取得を有効にできるモードを用意する。

目的:

- 利用者が手入力だけで使える状態を維持する
- 必要な利用者は、銘柄ティッカーとUSD/JPYだけを外部サービスへ照会できる
- 建玉数量、口座残高、証拠金、JSONバックアップなどの入力データは外部送信しないことを明示する

初回ON時の同意文:

```text
外部株価・為替取得を有効にします。

この機能をONにすると、株価取得時に銘柄ティッカー、為替取得時にUSD/JPY取得リクエストが外部の価格取得サービスへ送信されます。

送信される可能性があるもの:
- 銘柄ティッカー（例: NVDA, AMZN）
- USD/JPYの取得リクエスト
- 利用者のIPアドレス、ブラウザ情報、アクセス時刻

送信しないもの:
- 保有株数
- 建玉数量
- プレミアム
- 口座残高
- 証拠金使用率
- DEMO/REALの入力内容全体
- JSONバックアップの内容
- localStorageに保存されたデータ

外部取得を使わない場合は、Saxo TraderGO等で確認した株価・為替を手入力してください。
```

UI:

- ヘッダーまたはデータ/設定画面に `外部取得` トグルを置く
- 初期値はOFF
- ONにする時だけ同意ダイアログを出す
- 同意済みフラグはブラウザ内 `localStorage` に保存する
- OFFの場合、株価・為替ボタンは無効または `外部取得OFF` と表示する
- ONの場合、株価・為替ボタンを使用可能にする
- いつでもOFFへ戻せる

実装上の注意:

- 外部取得ONでも、送信するのは価格取得に必要な最小情報に限定する
- URLに建玉ID、数量、口座種別、残高、証拠金、メモを含めない
- 一括株価更新では、登録されているティッカーの集合だけを送る
- 公開版でAPIプロキシを使う場合は、プロキシ側でも入力データ全体をログに残さない
- 外部取得ON/OFFはJSONバックアップの対象外でもよい。端末ごとのプライバシー設定として扱う

表示文言:

```text
外部取得ON: 銘柄ティッカーとUSD/JPY取得リクエストのみ外部サービスへ送信します。
外部取得OFF: 株価・為替は手入力してください。
```

P/Nを合算した警告判定はしない。

#### 8.3.1 決済実績の現金残高反映

口座全体カードの `現金残高` は、原則としてSaxo画面下部から利用者が転記する口座スナップショットである。決済実績を入力しても、アプリが自動で勝手に現金残高へ加算・減算してはいけない。Saxo画面を見て転記した残高と二重計上になる可能性があるためである。

ただし、利用者が明示的に反映したい場合に限り、口座カードに `未反映の現金増減` を表示し、`現金残高に反映` ボタンを置く。

反映に使う金額:

- P口座 / DEMO_JPY_BASE: Saxo取引履歴の `記帳額 (JPY)` を使う
- N口座 / PROD_N_USD_SETTLEMENT: USDの買戻しコストとUSD手数料からUSD現金増減を使う
- `実現損益 (JPY)` は税務・成績用であり、現金残高へ反映する金額として使わない

例:

```text
P口座の買い決済:
実現損益 (JPY): +15,491  -> 税務・成績・年率に使う
記帳額 (JPY): -2,461     -> 現金残高へ反映する場合に使う
```

二重反映防止:

- 反映ボタンを押したら `AccountState.cashAdjustments` に `sourceExecutionId` と金額を記録する
- 同じ決済実績IDは二度反映できない
- 反映後にSaxo画面の最新残高を手入力する場合は、利用者が二重反映にならないよう注意文を表示する
- 現金残高へ反映するために必要な `記帳額 JPY` が未入力のP口座決済では、反映ボタンを無効化し、記帳額入力を促す

表示例:

```text
未反映の現金増減
NVDA P 200 2026-06-05 / 2026-06-02
-2,461円
[現金残高に反映]
```

入力欄は、SaxoTraderGO画面下部の並びに合わせる。

DEMO / JPYベース、P口座:

```text
現金残高（未受渡分込み）
買付可能額
口座純資産
必要証拠金余力
証拠金使用率
```

N口座:

```text
USD現金残高
USD買付可能額
USD口座純資産
必要証拠金余力
証拠金使用率
参考JPY換算
```

表示しない・使わないラベル:

```text
必要証拠金余力（JPY）
必要証拠金余力（USD）
```

理由:

- Saxo画面の第一面に表示されるのは `必要証拠金余力`
- `必要証拠金` と表示すると、ユーザーがSaxo画面で該当項目を探せず入力しづらい
- アプリのリスク判定では、口座全体の証拠金状態は `証拠金使用率` と `必要証拠金余力` で確認する
- 個別建玉の使用証拠金は、別途 `チケット表示証拠金 × 証拠金バッファ` で扱う

### 8.4 建玉入力

最初に口座を選ぶ。

```text
口座:
P: 外国株式等オプション（円建て / JPY決済）
N: 外国株式等オプション（ドル建て / USD決済）
```

口座に応じて入力ラベルを変える。

P口座:

- JPY決済額
- 適用為替
- JPY手数料（画面上でJPY手数料が確認できる場合だけ入力）
- 取引手数料（USD）

N口座:

- USDプレミアム
- 取引手数料（USD）
- 参考USD/JPY

新規建玉時の既定値:

- 取引手数料（USD）: `2.25 USD`
- JPY手数料: Saxo画面上でJPY手数料が確認できる場合だけ入力する補助的な任意入力
- NISA等 比較年率: `9%`

理由:

- Saxoのオプションチケットでは取引手数料が `2.25 USD` のようにUSDで表示されるため、建玉時の手数料初期値は取引手数料（USD）を主に使う
- JPY手数料はSaxo画面に明示されない場合があるため、補助的な任意入力として扱い、既定値では主計算へ強制しない
- NISA等比較年率は、ユーザーが比較対象として使う前提値を `9%` から開始する

### 8.4.1 C売り分類

C売りは、現物株を保有しているカバードコールと、現物株を保有していないネイキッドコールを混同しない。

従来の `C売りの方針` は、現物株を保有しているカバードコール前提では次の2択でよい。

```text
1. 株を残したい
2. 株を売却されてもよい
```

ただし、ショートストラングルなどで現物株を保有せずにコールを売る場合は、上記2択では不適切である。未カバーのC売りには、次の分類を追加する。

```text
3. 現物なし・上抜け時は買戻し
```

UI補足文:

```text
現物株を保有せずにコールを売る前提です。株価が想定ラインを上抜けた場合は、逆指値などで買い戻して撤退する方針を確認します。急騰時や時間外の値飛びでは、想定より不利な価格で約定する可能性があります。
```

判定:

```text
coveredCallShares = 保有株数
shortCallShares = C売り枚数 * 100
coveredShares = min(coveredCallShares, shortCallShares)
nakedCallShares = max(0, shortCallShares - coveredCallShares)
```

- `nakedCallShares = 0`: カバードコール扱い。`株を残したい` / `株を売却されてもよい` を表示する
- `nakedCallShares > 0`: 未カバー部分をネイキッドコール扱いにする
- ネイキッドコールが含まれる場合は、`現物なし・上抜け時は買戻し` を選べるようにする
- 現物株が一部だけ足りない場合は、カバー済み部分と未カバー部分を分けて注意表示する

避ける表現:

- `現物なしで上値リスクを取る`
- `逆指値で損失限定`
- 現物がないC売りに対する `株を売却されてもよい`

ネイキッドコールで入力または確認する項目:

- 逆指値ライン
- 買戻し価格ライン
- 許容損失額
- 満期何日前までに判断するか
- 逆指値でもギャップ・流動性不足で想定より不利に約定する可能性の確認

### 8.5 出口ルール・表示設定

サクソバンク証券では、決済注文、IFD、IFD-OCO、OCO等により、オプション建玉の利確ラインまたは損切りラインを事前に設定できる。アプリでは、これを「発注機能」ではなく、Saxoへ入力する出口注文の設計メモとして扱う。

対象:

- プット売り
- カバードコール
- カバードコール＋追加P売り
- ショートストラングル
- ホイール中の各売り建てオプション

特に `P売りの方針 = 株を取得したくない` の場合は、満期放置ではなく、注文前に反対売買の出口を決める前提で扱う。

入力項目:

```ts
type ExitOrderPlan = {
  scope: "position" | "leg";
  legId?: string;
  mode:
    | "manual_only"
    | "after_entry_closing_order"
    | "attached_entry_exit_order";
  brokerOrderType?:
    | "none"
    | "closing_limit"
    | "closing_stop"
    | "oco"
    | "ifd"
    | "ifd_oco";
  profitTakeEnabled: boolean;
  profitTakePremiumKeepPercent?: number;
  profitTakeBuybackPriceUSD?: number;
  stopLossEnabled: boolean;
  stopLossType?: "buyback_price" | "stock_price_line" | "loss_amount";
  stopLossBuybackPriceUSD?: number;
  stopLossStockPriceUSD?: number;
  stopLossAmountJPY?: number;
  stopLossAmountUSD?: number;
  stopLossAmountCurrency?: "JPY" | "USD";
  latestCloseDaysBeforeExpiry?: number;
  latestCloseDaysBeforeExpiryUserSet?: boolean;
  memo?: string;
};
```

出口ルールは、原則として「建玉全体」ではなく「売り建てオプション脚ごと」に適用する。カバードコール＋追加P売りのようにC売りとP売りが同時に存在する場合、C脚とP脚では出口判断の意味が異なるため、同じ利確・損切り・満期前タイムリミットを無条件に両方へ表示しない。

脚ごとの扱い:

```text
P売り:
- 株を取得したくない場合、出口ルールは重要
- 利確、損切り、満期前タイムリミット、Saxo出口注文の使い方を表示する
- 反対売買判断では、現在のP買戻し価格を入力して判定する

C売り:
- 株を売却されてもよい場合、買戻し判断は通常不要
- 反対売買判断では「通常は買戻し不要。株を残したい場合だけ入力」と表示する
- 利確・損切り・満期前タイムリミットをP売りと同じ条件で自動表示しない

C売りで株を残したい場合:
- C脚専用の出口ルールを表示する
- 現在のC買戻し価格を入力して、株を残すための買戻しコストを確認する
- 出口ルールカードは単なるメモ欄にせず、反対売買判断のC買戻し価格入力へ誘導する

C売りで現物なし・上抜け時は買戻しの場合:
- ネイキッドコールまたは未カバー部分があるC売りとして扱う
- 上方向の損失リスクを明示する
- 逆指値ライン、買戻し価格ライン、許容損失額、満期前タイムリミットを表示する
- `逆指値あり` でも損失限定とは表示しない
- 急騰、時間外の値飛び、寄付きギャップ、流動性不足で想定より不利に約定する可能性を警告する
```

損失額ルールの通貨:

- P口座、DEMO / JPYベース: `stopLossAmountJPY` を主入力にする
- N口座: `stopLossAmountUSD` を主入力にする
- JPY換算は参考表示に留める
- N口座で `stopLossAmountJPY` をUSD判定に流用しない

UI上は `4. ルール・表示設定` を、次の2カードに分離する。

```text
4. 出口ルール
5. 表示・比較設定
```

`出口ルール` は、Saxoに置く出口注文、または手動判断用の利確・損切り基準だけを扱う。

`表示・比較設定` は、年率計算・分母比較・NISA等比較の前提だけを扱う。主分母とNISA等比較年率は出口注文とは別概念なので、出口ルールカード内に置かない。

表示する項目:

#### 4. 出口ルール

- Saxo出口注文の使い方
  - 使わない（手動判断）
  - 建玉後に決済注文を入れる
  - 新規注文と同時にIFD/OCOを入れる
- Saxo注文タイプ
  - なし
  - 決済指値
  - 決済逆指値
  - OCO
  - IFD
  - IFD-OCO
- 利確ルール
  - プレミアム50%確保
  - プレミアム60%確保
  - プレミアム80%確保
  - 任意%
- 利確買戻し価格
- 損切りルール
  - 買戻し価格
  - 株価ライン
  - 損失額
- 損切り買戻し価格または株価ライン
- 満期何日前までに決済判断するか
- Saxo決済注文メモ

出口ルールカードでは、売り脚が複数ある場合に脚ごとに表示を分ける。

表示例:

```text
P 80 2026-07-02
方針: 株を取得したくない
出口ルール: 必須に近い管理対象
利確: 60%確保
損切り: 損失額 6,400円
満期前判断: 14日前

C 95 2026-07-02
方針: 株を売却されてもよい
出口ルール: 通常は不要
株を残したい場合だけ、C買戻し価格を反対売買判断で確認

C 95 2026-07-02
方針: 現物なし・上抜け時は買戻し
出口ルール: 上抜け時の撤退ルールが必要
上抜けライン: 100 USD
損切り: 買戻し価格または許容損失額で管理
注意: 逆指値でもギャップ時は想定より不利に約定する可能性
```

カバードコール＋追加P売りの場合、P売り用に設定した利確・損切り・満期前タイムリミットをC売りへ自動適用しない。

C売りで `株を残したい` 場合の出口ルールカードは、次の目的で使う。

- 株を残すために、C売りを買い戻す可能性があることを明示する
- Saxoの決済チケットで確認すべき値が `C買戻し価格` であることを示す
- 反対売買判断カードの該当C脚へ移動する導線を置く
- 満期前の判断期限を設定し、期限到達時に警告を出す
- 利益確保そのものよりも、株を残すためにいくら払って閉じるかを確認する

表示例:

```text
C売り 95 2026-07-02
方針: 株を残したい

このC売りは、株を残すために買戻し判断を行う可能性があります。
Saxoの決済チケットでC買戻し価格を確認し、反対売買判断に入力してください。

[反対売買判断でC買戻し価格を入力する]
満期何日前までに判断: 7日前
```

このカードは、単なるメモ欄ではなく、判断期限と反対売買判断への導線を持つカードとする。

使い方:

1. 利用者が `C売りの方針 = 株を残したい` を選ぶ
2. 出口ルールカードに、C脚専用の判断期限と `反対売買判断へ` ボタンを表示する
3. 利用者はSaxoの決済チケットでC買戻し価格を確認する
4. `反対売買判断` のC脚カードへ入力し、株を残すための買戻しコストを確認する

したがって、このカードは「メモ用」ではない。Saxoに自動発注する機能でもない。手入力版では、C買戻し判断を忘れないための設定・導線・期限警告の役割を持つ。

#### 5. 表示・比較設定

- 主分母
- NISA等 比較年率

主分母は分母比較・年率換算の前提であり、出口注文の設定ではない。画面上も出口ルールとは分ける。

UIでは `Saxoで決済注文を設定する` と `建て注文に出口を添付する` の2つのチェックボックスを並べない。利用者には違いが分かりにくいため、1つの選択項目 `Saxo出口注文の使い方` に統合する。

選択肢の意味:

```text
使わない（手動判断）
= Saxoには出口注文を置かず、アプリの利確・損切りルールを見ながら手動判断する

建玉後に決済注文を入れる
= すでに建てた建玉に対して、あとから決済指値・決済逆指値・OCOをSaxoに置く

新規注文と同時にIFD/OCOを入れる
= これから建てる注文と同時に、利確・損切りの出口注文もSaxoに添付する
```

利確買戻し価格は、受取プレミアムと確保率から自動計算できる。

```text
利確買戻し価格 = 建てた時のプレミアム × (1 - プレミアム確保率)
```

例:

```text
建てた時のプレミアム 1.00 USD
80%利確
→ 利確買戻し価格 0.20 USD
```

満期前タイムリミットは、買いたくない・買えないプット売りでは重要項目として扱う。標準候補は `満期7日前` とする。ただし、利用者が `14日前` などに変更できるようにする。

`株を取得したくない` プット売りでは、次のどれかが未設定なら注意または注文前NG候補にする。

- 利確ルール
- 損切りルール
- 満期前タイムリミット
- Saxoで決済注文/IFD-OCOを使うか、手動監視にするかの選択

`株を取得してもよい` プット売りでは、上記を必須NGにはしない。ただし、任意の管理ルールとして設定できる。

### 8.5.1 Saxo注文タイプと利確・損切り表示の連動

`利確ルールを使う` と `損切りルールを使う` の2つのチェックボックスを、Saxo注文タイプと独立して並べると利用者が混乱する。原則として、Saxo注文タイプから表示・有効化するルールを自動決定する。

連動ルール:

```text
決済指値
→ 利確ルールのみ表示・有効化
→ 損切りルールは非表示または無効

決済逆指値
→ 損切りルールのみ表示・有効化
→ 利確ルールは非表示または無効

OCO
→ 利確ルールと損切りルールの両方を表示・有効化

IFD-OCO
→ 利確ルールと損切りルールの両方を表示・有効化

使わない（手動判断）
→ Saxo注文としては使わない
→ アプリ内の判断基準として、利確ライン・損切りラインを任意表示できる
```

チェックボックスを残す場合でも、文言は `利確ラインを表示する`、`損切りラインを表示する` とし、Saxoへ注文を置く意味に見えないようにする。

ただし推奨UIは、チェックボックスを主操作にせず、Saxo注文タイプに応じて必要な入力欄だけを出す方式である。

出口ルールカードの説明文:

```text
ここでは、Saxoに置く出口注文、または手動判断用の利確・損切り基準を決めます。途中決済時の現在価格は、下の反対売買判断に入力します。
```

反対売買判断側の説明文:

```text
Saxoの決済チケットに表示される現在の買戻し価格を入力し、出口ルールに到達しているか確認します。
```

### 8.5.2 満期前タイムリミット警告

`満期何日前までに決済判断するか` は、APIで現在プレミアムを取得できない手入力版でも警告に使える。

警告条件:

```text
latestCloseDaysBeforeExpiry が設定されている
かつ 現在日付 >= 満期日 - latestCloseDaysBeforeExpiry
かつ 建玉状態が planned または open
かつ closed / assigned / expired ではない
```

警告文例:

```text
満期前の判断期限に到達しています。反対売買判断で現在の買戻し価格を確認してください。
```

`株を取得したくない` プット売りでは、満期前タイムリミット超過を強めの警告にする。

警告の表示場所:

- 建玉ダッシュボードの警告列
- サマリーカードの `最大注意点`
- リスク警告カード
- 該当する出口ルールカード内

警告は、単なる文字表示で終わらせない。警告には `反対売買判断へ` ボタンまたはクリック可能なリンクを付ける。クリック時は、反対売買判断カードを自動で開き、該当する脚の入力欄までスクロールする。

脚別の警告文例:

```text
P売り・株を取得したくない:
満期前の判断期限に到達しています。P買戻し価格を反対売買判断で確認してください。

C売り・株を残したい:
株を残したい方針のC売りです。判断期限に到達しています。C買戻し価格を反対売買判断で確認してください。

C売り・現物なし・上抜け時は買戻し:
現物なしのC売りです。判断期限に到達しています。上抜け時の買戻し価格または逆指値ラインを反対売買判断で確認してください。
```

クリック先:

```text
P売り警告 → close-decision-put-{legId}
C売り警告 → close-decision-call-{legId}
```

クリック後の挙動:

- 反対売買判断カードが畳まれている場合は開く
- 該当脚の入力欄が見える位置までスクロールする
- 可能であれば、現在の買戻し価格入力欄へフォーカスする

### 8.6 反対売買判断

反対売買判断は、現在のSaxo決済チケット価格を入力し、出口ルールに到達しているかを確認する領域とする。発注機能ではない。

表示する項目:

- 建てた時のプレミアム
- 現在の買戻し価格
- 建てた時の手数料
- 買戻し時の想定手数料
- 今閉じた場合の概算損益
- 今閉じた場合の年率
- プレミアム確保率
- 利確ルール判定
- 損切りルール判定
- 満期前タイムリミットまで残り何日
- Saxoで設定する決済指値・決済逆指値の目安

反対売買判断も脚ごとに表示内容を変える。

P売り:

- P買戻し価格入力欄を表示
- 利確ルール判定を表示
- 損切りルール判定を表示
- 満期前タイムリミットを表示
- Saxo決済注文目安を表示

C売りで `株を売却されてもよい`:

- C買戻し価格入力欄は折りたたむ、または任意表示にする
- 利確ルール判定、損切りルール判定、満期前タイムリミットをP売りと同じ条件で表示しない
- 説明文を表示する

```text
このC売りは、株を売却されてもよい方針です。通常は買戻し判断を行いません。株を残したい場合だけ、買戻し価格を入力してコストを確認してください。
```

C売りで `株を残したい`:

- C買戻し価格入力欄を表示
- C脚専用の買戻し判断として表示
- P脚用の損切りルールや満期前タイムリミットを流用しない
- 出口ルールカードから該当C脚の入力欄へジャンプできるようにする

C売りで `現物なし・上抜け時は買戻し`:

- C買戻し価格入力欄を表示
- 上抜けライン、買戻し価格ライン、許容損失額の判定を表示
- ネイキッドコールまたは未カバー部分の上方向リスクを表示
- `逆指値で損失限定` とは表示しない
- 逆指値を設定していても、急騰、時間外の値飛び、寄付きギャップ、流動性不足で想定より不利に約定する可能性を表示する
- P売り用の買受資金チェックとは分けて表示する

反対売買判断カードには、脚ごとに安定したアンカーIDを付ける。

```text
close-decision-call-{legId}
close-decision-put-{legId}
```

出口ルールカードや警告から該当アンカーへスクロールできるようにする。

判定例:

```text
建てた時のプレミアム: 1.07 USD
利確ルール: 60%確保
利確買戻し価格: 0.43 USD以下
現在の買戻し価格: 0.40 USD
判定: 利確ライン到達
```

損切り例:

```text
損切りルール: 買戻し価格 2.00 USD以上
現在の買戻し価格: 1.80 USD
判定: 未到達
```

反対売買判断で入力した買戻し価格は、出口ルール判定と同期する。建玉入力欄と反対売買判断欄で同じ意味の入力を重複させない。入力場所は反対売買判断側を主とする。

#### 8.6.1 途中決済時の年率表示

反対売買判断では、現在の買戻し価格を入力した時点で、`今閉じた場合の概算損益` だけでなく `今閉じた場合の年率` も表示する。

目的:

- プレミアム確保率だけでは、資金効率が分からない
- 途中決済で実際に得られる損益を、使用した期間と分母に対して年率換算する
- 満期まで保有した場合の年率と、途中決済した場合の年率を区別する

計算式:

```text
途中決済年率 =
  今閉じた場合の概算損益（手数料後）
  ÷ 使用分母
  × (365 ÷ 建玉日から反対売買判断日までの実経過日数)
  × 100
```

日数:

```text
holdingDays = max(1, 反対売買判断日 - 建玉日)
```

- 満期日までの日数ではなく、建玉日から反対売買判断日までの実経過日数を使う
- 当日中の判断では0日割りを避けるため、最低1日として扱う
- 反対売買判断日は、通常は今日の日付を使う
- 将来的に決済日入力を追加する場合は、その決済日を使う

分母:

- 画面上で選択されている主分母を使う
- P口座、DEMO / JPYベースではJPY損益 ÷ JPY分母
- N口座ではUSD損益 ÷ USD分母を主計算にし、JPYは参考表示にする

表示例:

```text
今閉じた場合の概算損益（手数料後）: +15,415円
今閉じた場合の年率: 123.4%
計算: 15,415円 ÷ 使用分母 × (365 ÷ 7日)
```

注意:

- これは途中決済時点の概算年率であり、満期まで保有した場合の年率とは別物
- 買戻し価格や手数料を入力していない場合は `未計算` と表示する
- 損益がマイナスの場合は、途中決済年率もマイナス表示にする

#### 8.6.1.5 建玉約定確認

`注文前` と `建玉中` では、入力値の意味が変わる。

- `注文前`: Saxoの注文チケットを見ながら入れる予定値
- `建玉中`: Saxoで実際に約定した後の建玉実績値

そのため、建玉状態を `注文前` から `建玉中` に変更した時は、`オプション脚` の入力欄をそのまま放置せず、`建玉約定確認` カードへ自動で移動する。

目的:

- 注文前の予定値を、約定後の正しい値へ確認・修正する
- 利用者がどこを直せばよいか迷わないようにする
- 予定値ベースの計算と、実績値ベースの計算を混同しない

追加するデータ型:

```ts
type OptionEntryExecution = {
  id: string;
  legId: string;
  tradeDate: string;
  contracts: number;
  fillPriceUSD: number;
  settlementCurrency: "JPY" | "USD";
  brokerBookedAmountJPY?: number;
  brokerPremiumJPY?: number;
  brokerTransactionCostJPY?: number;
  brokerNetPremiumJPY?: number;
  brokerFeeJPY?: number;
  brokerExchangeFeeJPY?: number;
  brokerExchangeConversionFeeJPY?: number;
  brokerExchangeFeeExchangeJPY?: number;
  brokerFeeConsumptionTaxJPY?: number;
  brokerExchangeRateJPY?: number;
  commissionUSD?: number;
  commissionJPY?: number;
  referenceFxRateJPY?: number;
  inputMode?: "P_JPY_BROKER_STATEMENT" | "USD_EXECUTION_CALC";
  source: "manual" | "broker_statement" | "saxo_api_estimate";
  confirmed: boolean;
  memo?: string;
};

type TradeSimulation = {
  optionEntryExecutions?: OptionEntryExecution[];
};
```

注文ID、ポジションID、約定時刻は通常入力に出さない。日常の損益管理・年率計算・税務区分集計には不要であり、UIを複雑にするためである。必要な場合はメモ欄に任意で書ける程度にとどめる。

`注文前` から `建玉中` へ変更した時の自動導線:

- 売り建てオプション脚ごとに `OptionEntryExecution` 下書きを自動作成する
- 既に対象脚の下書きがある場合は重複作成しない
- 現在のオプション脚入力値を初期値としてコピーする
  - `tradeDate`: 現在の建玉日
  - `contracts`: 対象脚の数量
  - `fillPriceUSD`: 対象脚のプレミアムUSD
  - `settlementCurrency`: 口座分類に応じて `JPY` または `USD`
  - `brokerExchangeRateJPY`: P口座 / DEMOなら現在の為替
  - `commissionUSD`: N口座のみ既定値 `2.25`。P口座 / DEMOでは通常入力に出さない
  - `source`: `manual`
  - `confirmed`: `false`
- `建玉約定確認` カードを自動で開き、画面をスクロールする
- P口座 / DEMOでは `記帳額 (JPY)` を最小入力の中心にする。`プレミアム (JPY)` と `取引費用 (JPY)` は確認・内訳用として同じカード内に置く。`為替レート`、詳細内訳は折りたたみまたは補助欄にする
- N口座では `USD約定価格`、`USD手数料`、`USD実現損益/プレミアム` を入力しやすく強調する
- 利用者が確認を終えたら `約定情報を確認済みにする` ボタンで `confirmed: true` にする

P口座 / DEMO_JPY_BASE の建玉約定入力:

Saxo取引履歴では、建玉時に次のような情報が見える。

```text
売 / 建玉
価格
数量
取引日
記帳額 (JPY)
取引費用 (JPY)

詳細:
プレミアム
手数料
為替変換手数料
取引所手数料
手数料・消費税額
為替レート
```

P口座の最小入力欄:

- 対象脚: 自動選択
- 取引日: Saxo履歴の取引日。建玉日から初期入力
- 約定価格 USD: Saxo履歴の価格。注文前のプレミアムUSDから初期入力
- 数量: Saxo履歴の数量。注文前の数量から初期入力
- 記帳額 JPY: Saxo履歴の行に出る `記帳額 (JPY)`
- プレミアム JPY: Saxo詳細の `プレミアム`
- 取引費用 JPY: Saxo詳細の `取引費用`。記帳額を再計算するための必須欄ではなく、費用確認用
- メモ

P口座の補助欄:

- 為替レート
- 詳細内訳: 手数料 JPY、為替変換手数料 JPY、取引所手数料 JPY、手数料・消費税額 JPY

補助欄は初期表示で大きく出さない。`詳細を開く` で表示する。

P口座では `取引手数料 USD` を通常入力に出さない。P口座のSaxo履歴では手数料・費用はJPYで表示されるため、USD手数料を残すと二重入力・二重控除の原因になる。

P口座の主計算:

```text
建玉時の現金反映額 JPY = 記帳額 JPY
```

`手数料控除後受取額 JPY` という表現は使わない。Saxo画面上の意味に合わせ、`記帳額 JPY` または `現金反映額 JPY` と表記する。

`取引費用 JPY` は、Saxo画面のように `-541 JPY` とマイナスで入力しても、`541` と正で入力してもよい。内部では費用情報として正規化する。ただし、`記帳額 JPY = プレミアム JPY - abs(取引費用 JPY)` として一律に計算してはいけない。

記帳額との関係:

- `記帳額 JPY` は、P口座の建玉時キャッシュフローとして最優先する
- `プレミアム JPY` は、受取プレミアムの確認用である
- `取引費用 JPY` は、費用確認用である
- Saxoでは `記帳額 JPY` と `取引費用 JPY` の控除範囲が完全一致しない場合があるため、`取引費用 JPY` から `記帳額 JPY` を再計算しない
- 例: プレミアム 18,308 JPY、記帳額 17,952 JPY、取引費用 -541 JPY の場合、アプリの現金反映額は 17,952 JPY であり、18,308 - 541 = 17,767 JPY とはしない

自動計算:

- `記帳額 JPY` が入力されたら、`現金反映額 JPY` としてそのまま表示する
- `プレミアム JPY` と `記帳額 JPY` が入力されている場合、`記帳額との差額 = プレミアム JPY - 記帳額 JPY` を参考表示してもよい
- `取引費用 JPY` が入力されている場合は、差額との比較を参考表示する。ただし不一致を計算エラーにしない
- `記帳額 JPY` が未入力の場合だけ、`プレミアム JPY` と費用内訳から `概算記帳額` を参考表示してよい。その場合は必ず `概算` と明示する

Saxo画面で費用がマイナス表示される場合、入力欄はマイナス入力も許容する。ただし内部計算では「費用」として絶対値または正のコストに正規化し、二重控除しない。

P口座では、SaxoのJPY実績を優先する。

- `プレミアム JPY` と `取引費用 JPY` が入力されている場合、建玉時の純受取額はそれを優先する
- 未入力の場合だけ、USDプレミアム × 為替から概算する
- 概算値を使う場合は `概算` と表示する
- Saxo実績値を使う場合は `Saxo実績ベース` と表示する

N口座 / PROD_N_USD_SETTLEMENT の建玉約定入力:

N口座はUSDが主帳簿であるため、建玉約定入力はUSDベースを主にする。

- 対象脚
- 取引日
- 約定価格 USD
- 数量
- USD手数料
- USDプレミアム
- 参考為替
- 参考JPY換算
- メモ

N口座ではJPY欄を主入力にしない。

未確認時の扱い:

- `建玉中` だが `OptionEntryExecution.confirmed` が `false` の場合、ダッシュボードまたは該当カードに `約定情報未確認` を表示する
- これは注文前NGではなく、実績入力の注意である
- 計算は既存のオプション脚値で継続できるが、`予定値ベース` または `約定未確認` と表示する
- 警告をクリックすると `建玉約定確認` カードへスクロールする

#### 8.6.1.6 建玉状態ワークフロー・ナビゲーション

建玉状態の変更は、単なるプルダウンではなく、次に必要な入力へ進むワークフローとして扱う。

目的:

- 利用者が「どこで状態を変えるか」を一目で分かるようにする
- 状態変更後に必要な実績入力へ迷わず移動できるようにする
- 入力漏れ、予定値と実績値の混同、履歴集計ミスを減らす

追加する派生型:

```ts
type WorkflowTaskType =
  | "confirm_entry_execution"
  | "enter_close_execution"
  | "confirm_expiry"
  | "enter_stock_acquisition"
  | "enter_stock_settlement"
  | "review_close_decision"
  | "complete";

type WorkflowTask = {
  id: string;
  simulationId: string;
  type: WorkflowTaskType;
  severity: "info" | "warning" | "danger";
  label: string;
  detail: string;
  actionLabel: string;
  targetAnchor:
    | "option-entry-executions"
    | "option-close-executions"
    | "stock-acquisition"
    | "stock-settlement"
    | "close-decision"
    | "simulation-editor";
  focusField?: string;
};
```

`WorkflowTask` は原則として保存データではなく、`TradeSimulation` から都度計算する派生データとする。JSONバックアップに保存しない。

タスク判定:

| 状態 | 条件 | 次にやること | targetAnchor |
| --- | --- | --- | --- |
| `注文前` | 注文前 | 注文内容を確認 | `simulation-editor` |
| `建玉中` | `optionEntryExecutions` が未作成または未確認 | 約定確認へ | `option-entry-executions` |
| `建玉中` | 約定確認済み | 反対売買判断 / 満期待ち | `close-decision` |
| `決済済み` | 決済実績なし、または未完成 | 決済実績を入力 | `option-close-executions` |
| `満期終了` | 満期終了履歴なし、または未確認 | 満期終了を確認 | `option-close-executions` |
| `権利行使済み` | P売りの株式取得記録なし | 株式取得を記録 | `stock-acquisition` |
| `権利行使済み` | C売りの株式譲渡記録なし | 株式譲渡を記録 | `stock-settlement` |
| 結果状態 | 必要記録がすべて完了 | 入力完了 | なし |

ダッシュボード表示:

- `次にやること` 列には、その建玉の最優先タスクを1つ表示する
- 複数タスクがある場合は `未完了2件` のように表示し、クリックで詳細を開く
- `danger` は赤、`warning` はオレンジ、`info` は青またはグレーで表示する
- ただし `info` は警告件数には含めない

状態変更UI:

`建玉状態` は、フォームの途中に埋め込むだけではなく、編集画面上部に `状態ステッパー` として表示する。

```text
注文前 -> 建玉中 -> 決済済み / 権利行使済み / 満期終了
```

- 現在状態を色付きで強調する
- 次に選べる状態をボタン化する
- 状態変更のプルダウンは残してもよいが、主導線はステッパーまたは状態変更ボタンにする
- 状態変更ボタンを押した直後に、必要な下書きを作成し、次の入力カードへ移動する

状態変更後の通知:

状態変更後、画面上部またはカード上部に短いガイドを表示する。

`注文前` -> `建玉中`:

```text
建玉中に変更しました。次にSaxoの取引履歴を見ながら約定情報を確認してください。
```

ボタン:

```text
約定確認へ進む
```

`建玉中` -> `決済済み`:

```text
決済済みに変更しました。次にSaxoの注文履歴から決済実績を入力してください。
```

ボタン:

```text
決済実績へ進む
```

`建玉中` -> `権利行使済み`:

```text
権利行使済みに変更しました。必要な株式取得または譲渡の記録を入力してください。
```

`建玉中` -> `満期終了`:

```text
満期終了に変更しました。買戻しなしでプレミアムが確定した履歴を確認してください。
```

ハイライト:

- 自動で移動したカードは、3〜5秒だけ淡いオレンジ枠または青枠で強調する
- 未入力の主項目は淡い背景色を付ける
- 入力完了または確認済みにしたら通常色へ戻す
- ハイライトは画面再読み込み後まで保存しない

実装方針:

- `getWorkflowTasks(simulation): WorkflowTask[]` をdomain層に作る
- `Dashboard` は `getWorkflowTasks` の最優先タスクを `次にやること` 列に表示する
- `SimulationEditor` は状態変更時に必要な下書きを作成し、`targetAnchor` へスクロールする
- スクロール処理は共通関数 `navigateToWorkflowTask(task)` または同等のUI関数にまとめる
- カードには安定した `id` を付ける
  - `option-entry-executions`
  - `option-close-executions`
  - `stock-acquisition`
  - `stock-settlement`
  - `close-decision`
- 折りたたみカードは、ナビゲーション時に自動で開く

完了条件:

- ダッシュボードだけを見ても、各建玉で次に何をすればよいか分かる
- 状態変更場所が一目で分かる
- 状態変更後、該当入力カードへ自動移動する
- そのカードが一時的に色で強調される
- 未入力欄が分かる
- 入力完了後、次にやることが `入力完了` または次のタスクに変わる

#### 8.6.2 決済実績記録

`反対売買判断` と `決済実績記録` は分ける。

`反対売買判断` は、Saxoの決済チケットに表示される現在価格を入れて、途中決済するかどうかを判断するための概算領域である。ここに入力した買戻し価格は、まだ実際の約定結果ではない。

`決済実績記録` は、Saxoで買戻し注文が実際に約定した後、Saxoの注文履歴詳細を見ながら入力する実績領域である。建玉状態を `決済済み` にする場合は、原則としてこの実績記録を入力する。

追加するデータ型:

```ts
type OptionCloseExecution = {
  id: string;
  legId: string;
  closeDate: string;
  contracts: number;
  closePriceUSD?: number;
  commissionUSD?: number;
  commissionJPY?: number;
  fxRateJPY?: number;
  settlementCurrency: "JPY" | "USD";
  brokerBookedAmountJPY?: number;
  brokerRealizedPnlJPY?: number;
  brokerTransactionCostJPY?: number;
  brokerPremiumJPY?: number;
  brokerFeeJPY?: number;
  brokerExchangeFeeJPY?: number;
  brokerExchangeConversionFeeJPY?: number;
  brokerFeeTaxJPY?: number;
  brokerExchangeRateJPY?: number;
  inputMode?: "P_JPY_BROKER_STATEMENT" | "USD_EXECUTION_CALC";
  source: "manual" | "broker_statement" | "saxo_api_estimate";
  memo?: string;
};

type TradeSimulation = {
  optionCloseExecutions?: OptionCloseExecution[];
};
```

入力項目の原則:

- 対象脚は通常カード見出しで表示し、単一脚では入力欄にしない
- 約定数量は対象脚の数量を初期値にし、部分決済の時だけ編集欄を開く
- 決済時刻、注文ID、ポジションID、取引番号は通常入力には出さず、必要時のメモに留める
- P口座 / DEMOではSaxoのJPY実績値を主入力にする
- N口座ではUSD実績値を主入力にする

決済実績カードは、P口座 / DEMO と N口座で入力欄を切り替える。共通UIとして `決済時手数料 USD` を常に主入力にしてはいけない。

注文ID、ポジションID、決済時刻は通常入力には出さない。利用者にとって日常的な損益管理、年率計算、税務区分集計には不要な識別情報であるため、必要な場合はメモ欄に任意で記録する程度にとどめる。

P口座 / DEMO_JPY_BASE の入力モード:

SaxoのP口座では、取引履歴に以下のJPY実績が表示される。P口座の決済実績入力では、この表示順に近い形で入力欄を並べる。

```text
銘柄
売買
新規/決済
価格
数量
取引日
記帳額 (JPY)
実現損益 (JPY)
取引費用 (JPY)

詳細:
手数料
為替変換手数料
取引所手数料
プレミアム
手数料・消費税額
為替レート
```

P口座での最小入力欄:

- 対象脚: 自動選択。通常はカード見出しに表示し、単一脚なら入力欄にしない
- 決済日 / 取引日: Saxo履歴の取引日
- 約定価格 USD: Saxo履歴の価格。反対売買判断に入力済みなら初期値にする
- Saxo実現損益 JPY: Saxo履歴の `実現損益 (JPY)`

P口座の照合用補助欄:

- 記帳額 JPY
- 取引費用 JPY
- 為替レート
- 約定数量
- メモ: 必要なら注文ID、ポジションID、取引番号などを任意で記録

補助欄は初期表示で大きく出さない。`照合用の詳細を開く` で表示する。

`照合用の詳細を開く` の中でも、最初から多数の費用内訳入力を並べない。利用者がSaxo履歴から通常確認したいのは、主に `記帳額 JPY`、`取引費用 JPY`、`為替レート` である。

手数料内訳は、さらに小さい `費用内訳を個別に記録する` を開いた場合だけ表示するか、メモ欄に残せるようにする。

費用内訳の任意項目:

- プレミアム JPY
- 手数料 JPY
- 為替変換手数料 JPY
- 取引所手数料 JPY
- 手数料・消費税額 JPY

これらは通常の損益計算には使わない。Saxoの表示を監査・照合したい場合だけ入力する。

P口座 / DEMO_JPY_BASE では、JPYの実績値を主入力にする。

- `実現損益 JPY` は主入力
- `取引費用 JPY` は照合用。`実現損益 JPY` 入力済みなら損益計算で追加控除しない
- `記帳額 JPY` は照合用。キャッシュフロー確認に使う
- `為替レート` は照合用。Saxo実現損益JPYがある場合は再計算に使わない
- `手数料 JPY`、`為替変換手数料 JPY`、`取引所手数料 JPY`、`手数料・消費税額 JPY` は詳細内訳として入力できる
- `決済時手数料 USD` は通常表示しない。SaxoのP口座履歴でUSD手数料が別途確認できる特殊ケースだけ、詳細欄に参考入力として置く
- `JPY手数料 任意` という表記は禁止する。P口座ではJPY費用が主であり、任意扱いに見せない

P口座の決済実績では、`Saxo実現損益 JPY` が入っていれば、それだけで税務区分別履歴、実現損益、決済実績年率を計算できるようにする。`取引費用 JPY` や詳細内訳は照合・メモ用途であり、`Saxo実現損益 JPY` に追加で差し引かない。

P口座の費用入力は、詳細内訳を全部入れなくてもよい。`取引費用 JPY` を入力した場合は照合用として表示し、詳細内訳を入力した場合は、`取引費用 JPY` と内訳合計が大きくずれていれば注意を出す。ただし、`実現損益 JPY` を上書き計算しない。

P口座では、`実現損益 JPY` が入力されている場合、その値を決済済みオプションの実現損益として優先する。これはSaxo側でJPY決済された実績値であり、アプリ側のUSD×為替による再計算より優先度が高い。

`実現損益 JPY` が未入力の場合は、可能であれば `記帳額 JPY` などから補助計算し、それもなければUSD約定価格と為替から概算する。ただし概算値であることを明示する。

P口座の最小入力例:

```text
決済日: 2026/06/02
約定価格 USD: 0.13
Saxo実現損益 JPY: 15,491
```

この3つがあれば、履歴、税務区分別集計、決済実績年率を計算できる。`記帳額 -2,461 JPY`、`取引費用 -384 JPY`、`為替レート 161.391940` は照合用詳細であり、通常入力では必須にしない。

P口座の画面例では、次のように解釈する。

```text
価格: 0.13               -> 約定価格 USD
数量: 1                  -> 自動数量。部分決済でなければ編集不要
取引日: 2026/06/02       -> 決済日
記帳額 (JPY): -2,461     -> 照合用の現金反映額
実現損益 (JPY): 15,491   -> 主計算に使う決済実績損益
取引費用 (JPY): -384     -> 照合用の費用。実現損益に追加控除しない
為替レート: 161.391940   -> 照合用。実現損益JPYがある時は再計算に使わない
```

したがって、通常入力の初期表示は `決済日`、`約定価格 USD`、`Saxo実現損益 JPY` の3項目に絞る。`記帳額 JPY`、`取引費用 JPY`、`為替レート`、詳細費用は `照合用の詳細を開く` の中に置く。

照合用詳細の表示階層:

```text
初期表示:
  - 決済日 / 取引日
  - 約定価格 USD
  - Saxo実現損益 JPY

照合用の詳細を開く:
  - 記帳額 JPY
  - 取引費用 JPY
  - 為替レート
  - 数量を変更（部分決済時だけ）
  - メモ

費用内訳を個別に記録する:
  - プレミアム JPY
  - 手数料 JPY
  - 為替変換手数料 JPY
  - 取引所手数料 JPY
  - 手数料・消費税額 JPY
```

費用内訳を個別に記録する領域は、初期状態では閉じる。入力しなくても、決済実績の履歴・税務集計・年率計算は成立する。

数量:

- 通常は対象脚の数量を自動使用する
- 部分決済の場合だけ `数量を変更` を開いて編集できるようにする
- 単一脚・全量決済では数量入力欄を常時表示しない

N口座 / PROD_N_USD_SETTLEMENT の入力モード:

N口座では、USDが主帳簿である。決済実績入力はUSDベースを主にし、JPYは参考換算に限定する。

N口座での推奨入力欄:

- 対象脚
- 取引日
- 約定価格 USD
- 数量
- USD手数料
- USD実現損益、またはアプリ計算のUSD実現損益
- 参考為替
- 参考JPY換算
- メモ: 必要なら注文ID、ポジションID、取引番号などを任意で記録

N口座では、P口座用の `記帳額 JPY`、`実現損益 JPY`、`取引費用 JPY` を主入力として扱わない。表示する場合も参考欄にとどめる。

N口座 / PROD_N_USD_SETTLEMENT では、USDの実績値を主入力にする。

- `USD手数料` は主入力
- `USDプレミアム` または `USD実現損益` は主入力
- `参考為替` は参考JPY換算のためだけに使う
- JPY費用欄を主入力として表示しない

Saxo注文履歴詳細との対応:

```text
買い決済 1プット @ 0.17
注文ID、ポジションID、受付/約定時間はSaxo上で確認できるが、アプリの通常入力項目にはしない
約定価格
約定数量
取引手数料
```

注意:

- Saxoの注文履歴詳細のタイトルに出る `買い決済 1プット @ 0.17` は注文価格であり、実際の約定価格とは異なる場合がある
- 実績入力で使う価格は、明細行の `約定` 行に表示される価格を優先する
- `注文済み` 行の価格は、発注時の指値としてメモ扱いにする
- P口座の取引履歴一覧に `実現損益 (JPY)` が表示されている場合は、その値を最優先で入力・集計する

計算:

共通のUSD計算は、Saxo実績JPYが取れない場合の概算またはN口座用である。P口座で `brokerRealizedPnlJPY` が入力されている場合は、以下のUSD再計算を主計算に使わない。

```text
建て時プレミアム = 建てプレミアムUSD × 100 × 枚数
買戻しコスト = 約定買戻し価格USD × 100 × 約定枚数
手数料 = 建て時手数料 + 決済時手数料

実現損益 = 建て時プレミアム - 買戻しコスト - 手数料
```

P口座、DEMO / JPYベース:

```text
実現損益JPY =
  (建て時プレミアムUSD - 買戻しコストUSD - 手数料USD)
  × 適用為替
  - JPY手数料
```

ただし、P口座のSaxo取引履歴で `実現損益 (JPY)` が確認でき、利用者が `brokerRealizedPnlJPY` に入力した場合は、その値を最優先する。

優先順位:

1. `brokerRealizedPnlJPY`: Saxo取引履歴の `実現損益 (JPY)`
2. `brokerBookedAmountJPY` など明細JPY値からの補助計算
3. USD約定価格、USD手数料、為替からのアプリ概算

1または2を使った場合は `Saxo実績ベース` と表示する。3を使った場合は `概算` と表示する。

`brokerRealizedPnlJPY` を使う場合、`brokerTransactionCostJPY`、`brokerFeeJPY`、`brokerExchangeFeeJPY` などをさらに控除しない。Saxoの実現損益JPYは、P口座の履歴上で確定表示された実績値として扱う。費用欄は照合・メモ用途である。

決済実績カードの計算内訳表示:

P口座 / DEMO_JPY_BASE で `brokerRealizedPnlJPY` が入力されている場合、緑色の結果欄の `計算内訳` にUSD式を表示しない。

表示例:

```text
計算内訳
Saxo実績ベース / 実現損益 15,491 JPYを採用
参考: 記帳額 -2,461 JPY / 取引費用 -384 JPY / 為替 161.391940
```

この場合、`プレミアム $116.00 - 買戻し $13.00 - 手数料 $5.63` のようなUSD式は出さない。P口座ではSaxoがJPYで確定表示した実現損益を採用しているため、USD式は概算説明としても前面に出すべきではない。

P口座で `brokerRealizedPnlJPY` が未入力で、USD約定価格・為替から概算している場合だけ、次のように明示する。

```text
計算内訳
概算 / USD価格と為替から参考計算。Saxo実現損益JPYを入力すると実績ベースになります。
```

N口座 / PROD_N_USD_SETTLEMENT の場合はUSDが主帳簿なので、USD式を表示してよい。

表示例:

```text
計算内訳
USD実績ベース / プレミアム $116.00 - 買戻し $13.00 - 手数料 $4.50
参考JPY換算: 18,xxx JPY
```

N口座:

```text
実現損益USD =
  建て時プレミアムUSD
  - 買戻しコストUSD
  - USD手数料

JPYは参考換算だけにする。
```

税務集計:

- `closed` かつ `optionCloseExecutions` あり: 決済実績から先物取引に係る雑所得等の実現損益を計算する
- `closed` だが `optionCloseExecutions` なし: 税務区分別履歴集計では `実績未入力` として注意表示する。推定値で確定集計しない
- `expired`: 権利行使されず満期終了した売り建ては、プレミアムから手数料を引いた金額を実現損益として扱う
- `assigned`: オプション損益はプレミアムから手数料を引いた金額。株式取得または譲渡は別カードで扱う

年率:

```text
決済実績年率 =
  決済実績損益
  ÷ 使用分母
  × (365 ÷ 建玉日から実際の決済日までの日数)
  × 100
```

- 決済日が入力されている場合は、反対売買判断日の代わりに実際の決済日を使う
- 決済実績年率は、履歴側のオプション実現損益にも表示する

UI:

`手入力ウィザード` に `7. 決済実績` カードを追加する。

表示条件:

- 建玉状態が `決済済み`
- または `反対売買判断` から `この価格で決済実績に反映` を押した場合

反対売買判断カードには、脚ごとに次のボタンを置く。

```text
この価格で決済実績に反映
```

クリック時:

1. 現在の買戻し価格を `closePriceUSD` にコピーする
2. 決済日を今日にする
3. 約定数量を対象脚の数量にする
4. 決済時手数料USDの初期値を `2.25` にする
5. `7. 決済実績` カードを開く
6. 利用者がSaxo注文履歴詳細を見ながら約定価格、数量、実際の手数料を修正できるようにする。IDや時刻が必要な場合はメモ欄に任意で記録する

建玉状態を `決済済み` に変更した時の自動導線:

- 利用者が建玉状態を `建玉中` から `決済済み` に変更した時点で、売り建てオプション脚ごとの `OptionCloseExecution` 下書きを自動作成する
- 既に対象脚の `OptionCloseExecution` がある場合は重複作成しない
- 下書きの初期値は以下とする
  - `closeDate`: 今日
  - `contracts`: 対象脚の数量
  - `closePriceUSD`: 反対売買判断に入力済みの買戻し価格があればその値、なければ空欄
  - `commissionUSD`: `2.25`
  - `settlementCurrency`: 口座分類に応じて `JPY` または `USD`
  - `source`: `manual`
- 下書き作成後、`7. 決済実績` カードを自動で開き、画面をスクロールする
- 可能であれば最初の未入力項目、通常は `約定価格 USD` にフォーカスする
- 自動作成された下書きは `未確定 / 入力中` の扱いにし、約定価格、数量、実際の手数料をSaxo注文履歴で確認してから保存・確定する導線にする。IDや時刻は必須にしない
- 利用者が誤って `決済済み` に変更した場合に備え、建玉状態を `建玉中` へ戻しても決済実績の下書きは自動削除しない。削除は利用者操作にする
- `決済済み` だが決済実績下書きが未完成の場合は、税務履歴・実現損益の確定集計には入れず、未入力警告を出す

建玉状態変更時の遷移先ルール:

`建玉状態` を `建玉中` から結果状態へ変更した場合は、戦略とオプション脚に応じて、利用者が次に入力すべきカードへ自動で移動する。

| 変更後の状態 | 対象脚 / 戦略 | 自動で開くカード | 目的 |
| --- | --- | --- | --- |
| `決済済み` | P売り / C売り / 複合戦略の各売り脚 | `7. 決済実績` | Saxo注文履歴の買戻し約定価格、約定日、手数料を記録する |
| `満期終了` | 権利行使されず失効したP売り / C売り | `7. 決済実績` の満期終了モード | 買戻しなしでプレミアムが確定した履歴を残す |
| `権利行使済み` | P売り | `5. 現物株の取得記録` または株式取得カード | P権利行使により株を買い受けた記録を作る |
| `権利行使済み` | カバードコール / C売り | `5. 現物株の譲渡記録` | C権利行使により株を渡した、または売却扱いになった記録を作る |
| `権利行使済み` | ネイキッドコールを含むC売り | `7. 決済実績` とリスク警告 | 現物がないため通常の譲渡記録だけでは完結しない。Saxo上の処理確認を促す |
| `権利行使済み` | カバードコール＋追加P売り | C脚は `現物株の譲渡記録`、P脚は必要に応じて `現物株の取得記録` | 複数脚が同時に結果状態を持つ可能性があるため、脚ごとに記録先を分ける |

`満期終了` の扱い:

- 満期終了は買戻し約定ではないため、`closePriceUSD` は `0` ではなく「買戻しなし」として扱う
- 実現損益は、受取プレミアムから建て時手数料を引いた金額とする
- 満期終了日を実現日として、履歴・税務区分別集計へ反映する
- UI上は `7. 決済実績` カード内に `満期終了モード` を用意し、約定価格欄を表示しない、または無効化する
- `満期終了` に変更したら、満期日を実現日として初期入力し、カードへスクロールする

`権利行使済み` の扱い:

- P売りの権利行使は、株式を買い受けるイベントである。`現物株の取得記録` に、取得日、取得株数、取得単価、手数料、口座区分を入力させる
- C売りの権利行使は、保有株を渡す、または売却扱いになるイベントである。`現物株の譲渡記録` に、譲渡日、譲渡株数、譲渡単価、取得単価、手数料、口座区分を入力させる
- オプション側のプレミアム損益は `先物取引に係る雑所得等`、株式取得・譲渡側は `上場株式等の譲渡所得等` として分ける
- `権利行使済み` に変更しただけで株式損益を自動確定しない。利用者が株式取得または譲渡の実績入力を完了してから集計する
- 複合戦略では、P脚とC脚を個別に判定し、必要な記録カードを複数表示できるようにする

カード移動の原則:

- 状態変更後は、最も入力漏れリスクが高いカードを開いてスクロールする
- 既に該当する実績下書きがある場合は重複作成しない
- 誤操作で状態を戻しても、作成済みの実績下書きは自動削除しない
- 下書きが未完成の間は、履歴・税務・年率の確定集計には入れず、未入力警告を出す

警告:

```text
決済済みですが、決済実績が未入力です。Saxo注文履歴から約定価格と手数料を入力してください。
```

この警告は次の場合に出す。

- `simulation.status === "closed"`
- 対象の売り建てオプション脚がある
- `optionCloseExecutions` が空、または対象脚の実績が不足している

この警告には `決済実績を入力` のアクションを付け、クリックで `7. 決済実績` カードへスクロールする。

保存・復元:

- JSONバックアップに `optionCloseExecutions` を含める
- 旧JSONでは `optionCloseExecutions` がなくても壊れない
- 旧データの `closeCostUSD` は判断用価格として残し、勝手に実績へ変換しない

### 8.7 ホイール戦略カード

画面下部にコンパクト表示する。

ホイール戦略カードは常時大きく表示しない。銘柄ごとのホイールサイクルが存在しない場合、または選択中の建玉がまだホイール管理に登録されていない場合は、折りたたみ行または小さな導線だけを表示する。

表示ルール:

- ホイールサイクルが0件: `ホイール管理 0件` と小さく表示し、必要な時だけ開く
- P口座プット売り中: `ホイール準備中（P口座）` として表示し、N口座ホイール本体と区別する
- P→N移管後またはN口座運用中: `N口座ホイール管理` として表示する
- ダッシュボードやサマリー確認の邪魔にならないよう、初期状態は折りたたむ
- ユーザーが `選択建玉からサイクル作成` を押した場合のみ、その建玉をホイール管理へ登録する
- P口座プット売りを登録する場合は、N口座現金待機を通過済みにしない

通常:

```text
ホイール戦略
NVDA | Nカバードコール中 | +$612 | 100株
AMZN | Nプット売り中     | +$180 | 0株
```

展開時:

- 色付きフェーズステッパー
- 累積損益
- 保有株数と平均取得単価
- イベント履歴
- 関連建玉
- 次の候補アクション

## 9. 計算ロジック

### 9.1 P口座プレミアム

実明細がある場合:

```text
netCashflowJPY = brokerNetCashflowJPY
```

推定の場合:

```text
grossPremiumUSD = premiumUSD * 100 * quantity
grossPremiumJPY = grossPremiumUSD * appliedFxRate
netCashflowJPY = grossPremiumJPY - commissionJPY - exchangeFeeJPY
```

### 9.2 N口座プレミアム

```text
grossPremiumUSD = premiumUSD * 100 * quantity
netCashflowUSD = grossPremiumUSD - commissionUSD - exchangeFeeUSD
referenceJPY = netCashflowUSD * referenceFxRateJPY
```

年率計算はUSD同士で行う。

```text
annualReturnPct = profitUSD / denominatorUSD * (365 / days) * 100
```

JPY参考換算は年率の主計算には使わない。

### 9.3 N口座ホイール累積損益

```text
cumulativePremiumUSD
  + cumulativeStockRealizedPnlUSD
  - cumulativeFeesUSD
  = cumulativeTotalPnlUSD
```

未売却の株式含み損益は、実現損益とは別に表示する。

### 9.4 カバードコール満期想定損益

カバードコールでは、権利行使された場合の株式売却損益とオプションプレミアムを並べて表示する。

```text
株式売却損益 = (C権利行使価格 - 取得単価) * 株数
オプション損益 = Cプレミアム - 手数料
合計想定損益 = 株式売却損益 + オプション損益
```

N口座ではUSD主表示、JPYは参考表示。

### 9.4.1 ショートストラングルとネイキッドコールの満期シナリオ

ショートストラングル、または現物株なしのC売りを含む建玉では、カバードコールと同じシナリオ文言を使わない。

ショートストラングルの表示:

```text
レンジ内:
P売りとC売りの両方が権利行使されず、プレミアム獲得を想定

下抜け:
P売りの権利行使で株を買い受ける可能性、またはPを買い戻して閉じる判断
P側は、下落時に買い受ける資金と方針を確認する

上抜け:
C売りの買戻し、または権利行使リスクを確認する
現物なしのC売りでは、売却する現物株がないため、上抜け時の買戻しルールと許容損失額を確認する
```

資金表示:

- P売り側: `下落時に買い受ける資金`
- C売り側: `上抜け時に買い戻す資金・許容損失額`

現物なしのC売りでは、上方向の最大損失を固定値として断定しない。逆指値ラインがある場合も、ギャップや流動性不足により想定より不利な価格で約定する可能性があるため、警告として表示する。

### 9.5 税務

オプション損益と株式譲渡損益は別区分で表示する。

N口座でUSD運用中の損益は、JPY換算を確定値として扱わない。税務上の厳密な円換算は後続フェーズ。

## 10. リスク警告

### 10.0 警告レベルと集計ルール

警告は、利用者が「本当に注文前に止めるべきもの」と「確認情報」を混同しないように分類する。

```ts
type RiskSeverity = "info" | "warning" | "danger";
```

表示上の意味:

```text
info:
  情報表示。警告件数・注意件数には含めない。
  例: N口座のJPY換算は参考表示。

warning:
  注意。注文前NGではないが、確認した方がよい。
  ダッシュボードでは「注意n件」に含める。

danger:
  重大警告。blocking=true の場合は「注文前NG」として扱う。
```

ダッシュボードの集計:

```text
info 件数: 警告列の件数に含めない
warning 件数: 注意n件
danger かつ blocking=true: NGn件
danger かつ blocking=false: 注意n件、または重大注意として表示
```

`N口座のJPY換算は参考表示です` のような常時表示の注意喚起は、リスク警告カードではなく、N口座カードやヘルプ内の情報表示として扱う。どうしてもリスク警告一覧に出す場合も `info` とし、ダッシュボードの警告件数には含めない。

追加する警告:

1. P/N余力の混同
   - P口座のJPY残高をN口座建玉の余力に使っている可能性
   - N口座のUSD残高をP口座建玉の余力に使っている可能性

2. P口座に取得株が残っている
   - P口座で権利行使により株式取得済み
   - N口座へ移管していない

3. N口座カバードコールの株数不足
   - C売り数量 * 100 > N口座保有株数

4. 同一口座内でP売りとカバードコールを同時進行
   - 資料上は、通常ホイールはN口座中心、P口座は入口・資金待機として分ける前提
   - 必ずNGではないが、注意表示する

5. N口座JPY換算の誤解
   - 参考換算を確定損益と誤認しないよう表示
   - `info` として扱い、警告件数・注意件数には含めない

6. 最終円転未記録
   - N口座からJPY出金したが、出金・円転イベントが未入力

7. 買いたくないプット売りの出口未設定
   - `P売りの方針 = 株を取得したくない` の場合、利確ルール、損切りルール、満期前タイムリミット、Saxo決済注文方針のいずれかが未設定なら注意表示する
   - すべて未設定の場合は注文前NG候補とする

8. 満期前タイムリミット超過
   - 利用者が明示的に設定した `latestCloseDaysBeforeExpiry` を過ぎているのに建玉が未決済の場合、反対売買判断を促す
   - デフォルト値として自動で入っているだけの期限では、期限超過警告を出さない
   - 買いたくないプット売りでは強めの警告にする
   - C売りで `株を残したい` 場合も、判断期限超過時にC買戻し判断を促す
   - 警告には `反対売買判断へ` のリンクまたはボタンを付け、該当脚の反対売買判断カードへスクロールする

9. ネイキッドコールまたは未カバーC売り
   - C売り数量 * 100 が保有株数を上回る場合、未カバー部分をネイキッドコールとして扱う
   - `現物なし・上抜け時は買戻し` の方針、逆指値ライン、買戻し価格ライン、許容損失額のいずれも未設定なら注意または注文前NG候補にする
   - 逆指値ありでも、急騰、時間外の値飛び、寄付きギャップ、流動性不足で想定より不利に約定する可能性を警告する
   - `逆指値で損失限定` とは表示しない
   - `未カバーC売りがある`、`上抜け時のルールが未設定`、`期限到達` を別々に重複表示しすぎない
   - 推奨は、一覧上は1件の主要警告にまとめ、詳細内で不足項目を列挙する方式

10. 為替レート未入力
   - P口座、DEMO / JPYベースでは、JPY計算に必須のため `danger` とする
   - N口座ではUSD主計算は可能だが、JPY参考表示と税務参考値が崩れるため、文言を分ける
   - N口座向け文言では「すべて0円になります」と断定しない

警告表示位置:

- 建玉ダッシュボードの警告列
- リスク警告カード
- 必要に応じて出口ルールカード内の該当脚

警告クリック時の動作:

```text
ダッシュボード警告またはリスク警告をクリック
→ 対象建玉を選択
→ 反対売買判断カードを開く
→ 対象脚の入力欄へスクロール
```

警告文例:

```text
満期前の判断期限に到達しています。C買戻し価格を確認してください。
```

```text
満期前の判断期限に到達しています。P買戻し価格を確認してください。
```

### 10.1 現行警告文の修正方針

現行実装で修正が必要な警告:

1. `N口座のJPY換算は参考表示です`
   - 内容は妥当
   - `info` として扱い、ダッシュボードの `注意n件` には含めない

2. `裸コール部分があります` / `裸コールの上方向ルールが未設定です` / `未カバーC売りの出口ルールが未設定です`
   - 方向性は妥当
   - ただし重複して見えやすいため、利用者向けには `未カバーC売りの確認が必要です` を主警告にし、不足項目を本文で列挙する
   - `裸コール` より `未カバーC売り` を基本文言にする

3. `N口座のUSD現金残高が不足している可能性があります`
   - 内容は妥当
   - 判定はUSD残高とUSD買付資金で行う
   - JPY換算値で判定しない

4. `許容損失額`
   - P口座、DEMOはJPY
   - N口座はUSD
   - N口座でJPYの許容損失額をUSD損益と比較しない

5. `満期前判断期限に到達しています`
   - 利用者が明示設定した期限だけ警告対象にする
   - `株を取得してもよい` P売りでは、デフォルト期限だけで警告を出さない
   - `株を取得したくない` P売り、`株を残したい` C売り、`現物なし・上抜け時は買戻し` C売りでは、明示設定済みなら警告対象にする

6. `買いたくないP売りとしては権利行使価格が近い可能性があります`
   - 内容は妥当
   - 判定根拠を文言に入れる
   - 例: `現在株価に対してP権利行使価格が近い水準です。距離、損切り、分母を確認してください。`

7. `証拠金使用率が高いです`
   - 内容は妥当
   - 閾値を文言に入れる
   - 例: `証拠金使用率が60%以上です。建玉追加や急変時の余力を確認してください。`

8. `為替レートが未入力です`
   - P口座、DEMOでは現行方針でよい
   - N口座では `N口座はUSD主計算ですが、JPY参考表示と税務参考値に使うUSD/JPYが未入力です。` のように分ける

## 13. 最適な実装順

最初にやるべき順番は次。

1. Phase 0: 保全
2. Phase 1: P/N口座基盤
3. Phase 2: P/N別計算
4. Phase 3: P→N株式移管
5. Phase 4: N口座ホイール可視化
6. Phase 5: 警告と文言
7. Phase 6: 税務・履歴集計
8. Phase 7: read-only連携

理由:

- 口座と通貨の土台を直さないままホイールを作ると、後で全面修正になる
- N口座ホイールはUSD台帳が前提なので、P/N別計算が先
- P→N株式移管はホイール合流の入口なので、ホイール可視化より先
- read-only連携は最後でよい。手入力で正しい設計を固めてから取得自動化する
