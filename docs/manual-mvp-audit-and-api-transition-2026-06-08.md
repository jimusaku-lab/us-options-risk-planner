作成日: 2026-06-08  
対象: 米国株オプション建玉管理・リスク確認アプリ  
対象バージョン:

- ローカル版: `http://127.0.0.1:5173/`
- 一般公開版: `https://jimusaku-lab.github.io/us-options-risk-planner/`
- グレードアップ開発版: ローカル高機能版

## 1. 結論

手入力版は、建玉管理アプリとして予定していた主要機能をほぼ満たしている。

今後は、手入力版へ大きな新機能を追加し続けるより、手入力版を一度MVPとして固定し、Saxo API read-onlyによる数値取得版へ設計の主軸を移す。

ただし、API版へ移る前に、3つのバージョンが同じ仕様に揃っているかを確認し、差分を解消してから固定する。

## 5. Saxo API版へ移る目的

次フェーズの主目的は、ユーザーがSaxo画面を見ながら転記していた数値を、read-onlyで取得し、入力負担と転記ミスを減らすことである。

API版でも発注はしない。

実装しないもの:

- Saxoへの注文作成
- 注文変更
- 注文取消
- SaxoTraderGO画面の自動クリック
- 条件に合う銘柄の自動発注

## 6. Saxo API版の基本アーキテクチャ

フロントエンドからSaxo OpenAPIへ直接接続しない。

```text
React/Vite UI
→ ローカルAPI
→ Saxo OpenAPI
```

理由:

- OAuthトークンをブラウザlocalStorageに置かない
- read-only制約をローカルAPI側で強制する
- Saxoのレスポンスをアプリの型へ正規化する
- 取得時刻、取得失敗、権限不足、キャッシュを管理する
- 将来も発注機能を混入させない

## 8. API版の実装フェーズ案

### Phase API-0: 手入力版固定

- 3バージョン差分確認
- ローカル版テスト

### Phase API-2: OAuth / 接続状態

- PKCE認証
- callback処理
- token refresh

- 接続状態UI

### Phase API-3: 口座・残高同期

- P/N口座候補の取得

- balances / margin overview取得

### Phase API-4: 現在建玉同期

### Phase API-6: オプションチェーン・反対売買判断

## 10. 次の設計判断

次に決めるべきことは、API版の最初の実装単位を「口座・残高取得」から始めるか、「現在建玉取得」から始めるかである。

推奨は `口座・残高取得` から始めること。

理由:

- P/N口座分類の土台になる
- 証拠金使用率、必要証拠金余力、現金残高の手入力負担が大きい
- 取得値とSaxo画面の照合がしやすい
- 建玉照合よりリスクが低い

### 工程1: 手入力版MVP固定

目的:

API版へ移る前に、現在の手入力版を「手入力MVP」として壊さない基準にする。

作業:

1. ローカル版で `npm test` を実行する
2. ローカル版で `npm run build` を実行する
3. 現在の主要機能が手入力MVPとして成立していることを確認する
4. READMEまたはマニュアルに、現行版は手入力MVPであり、Saxo API連携は未実装であることを明記する
5. 可能であればGitタグまたはブランチ名で固定する

推奨タグ名:

```text
manual-mvp-2026-06-08
```

完了条件:

- ローカル版のテストが通る
- ローカル版のビルドが通る
- 手入力MVPとしての位置づけがREADMEまたはマニュアルに明記されている
- Saxo API未実装であることが利用者に誤解されない

### 工程2: 3版差分確認と同期

目的:

ローカル版、一般公開版、グレードアップ開発版が、手入力MVPとして同じ仕様を持つ状態にする。

作業:

1. ローカル版と一般公開版の差分を確認する
2. ローカル版とグレードアップ開発版の差分を確認する
3. 差分を次の3種類に分類する
   - 意図した差分
   - 未展開の差分
   - 古い実装が残っている差分
4. 未展開の差分と古い実装を、原則としてローカル版の最新仕様へ揃える
5. 一般公開版で公開URL用の設定だけは維持する
6. 配布成果物だけの `pages-dist/us-options-risk-planner` は差分基準にしない
7. 同期後に各版でテストまたはビルドを実行する

同期対象として特に確認するもの:

- `当年成績サマリー` / `成績` 画面
- 建玉状態ワークフロー
- 建玉開始の約定確認
- 決済実績記録
- P口座 / N口座表示
- DEMO_JPY_BASE表示
- 外部取得ON/OFF廃止
- 株価・為替更新ボタン
- 税務区分別内訳
- JSONバックアップ / 復元
- マニュアル / 初回注意書き

完了条件:

- 3版で、手入力MVPとしての主要機能差分がない
- 意図した差分だけが一覧化されている
- 一般公開版が `https://jimusaku-lab.github.io/us-options-risk-planner/` で動く
- 公開版が `retirement-simulator` 配下へ誤って反映されていない
- ローカル版、一般公開版、グレードアップ開発版のどれを使っても、同じJSONデータで主要表示が同じになる
